# MusicLinkd

MusicLinkd is a professional network and marketplace for the music industry, with a customer-facing mobile app, public website, internal operations portal, and a shared design-system reference.

## Repository map

| Directory | Purpose |
| --- | --- |

| `frontend/guide/` | The design system. `index.html` is the live catalogue at `/guide`, generated by `scripts/build-guide.mjs`; `system/` holds the three stylesheets and `tokens/tokens.json` is the token source of truth. |

## Design system and UI governance

The design system is the UI source of truth. Before adding or changing a UI surface:

1. Check the existing system components, tokens, patterns, and documented flows.
2. Reuse an approved equivalent whenever one exists.
3. Do not introduce a duplicate component, token, card, or page pattern without documenting why.
4. Keep product UI, brand-expression assets, and implementation details aligned with the canonical system.

The design-system catalogue is generated from the repository rather than maintained as an independent hand-written component inventory. The build entry point is [`scripts/build-guide.mjs`](scripts/build-guide.mjs).

### Generators

| Command | Writes |
| --- | --- |
| `node scripts/build-tokens.mjs` | `frontend/guide/system/ml-tokens.css` and `webapp/shared/ml-tokens.css` from `tokens.json`. Fails over the token-count ceiling, or on a scale whose steps are not numbered 1…n without gaps. |
| `node scripts/build-guide.mjs` | `frontend/guide/index.html`. |
| `node scripts/build-handoff.mjs` | `docs/handoff/MusicLinkdTokens.kt` (Compose) and `MusicLinkdTokens.swift` (SwiftUI). Both are emitted from each token's own `$android` / `$ios` form, not translated from one another — the touch minimum is 48dp on Android and 44pt on iOS, and four other values differ the same way. |
| `node scripts/build-icons-lucide.mjs` | `frontend/guide/icons-lucide/` — 2006 SVGs extracted from the installed `lucide-react` (ISC). Fails if any icon does not parse, so a partial set can't ship looking complete. |

The system ships **two icon sets**: 423 filled Gestalt glyphs (the product set, inlined into screens at build time) and 2006 stroked Lucide outlines (the breadth set). They must not be mixed inside one control — see [frontend/guide/README.md](frontend/guide/README.md).

### Audits

Each one exists because the thing it measures was previously asserted rather
than checked, and the assertion was wrong.

| Command | Answers |
| --- | --- |
| `node scripts/audit-screens.mjs` | Do the preview screens resolve every token, link and class, and are they free of local `<style>` blocks? |
| `node scripts/audit-tokens.mjs` | Is any token dead, and does any stylesheet still write a literal where a token already names that value? Splits web-dead from native-only, because `--gesture-*` and `--component-*` are consumed by Compose, not CSS. |
| `node scripts/audit-guide-migration.mjs` | What did the superseded `styleguide.html` carry that the current guide still does not? Renames are aliased explicitly, so the count reflects real gaps rather than renamed sections. |

Every component in the catalogue also carries a **state map** — which of the
ten states it owns, inherits from the base layer, composes from another
component, or genuinely lacks. It is derived from the stylesheets, not listed
by hand. Absent states are shown struck through on purpose: a screen author who
can see that a component has no error state is told to build it in
`ml-widgets.css` rather than fork a second screen, which is how the flows
previously grew one screen per state.

## Backend and Firebase

MusicLinkd currently uses the Firebase project `musiclinkd-7ae30` across the Android app, website, and admin surfaces.

Repository-level Firebase configuration includes:

- `firebase.json`
- `firestore.rules`
- `firestore.indexes.json`
- `storage.rules`
- `remoteconfig.template.json`
- `.firebaserc`

The Firestore rules and indexes in this repository are the deployed ones
(`firestore.rules`, `firestore.indexes.json`). The prose schema and
build/environment guides that used to be linked here lived under `app/docs/`
and left with the Android application in `1620e46`; they are not in this
repository and the links to them were dead. For the schema as this repository
uses it, read the rules file and
[`admin/docs/architecture/`](admin/docs/architecture/).

## WordPress Block Theme & Production Website

The root repository includes the production Full Site Editing (FSE) block theme mapped for Hostinger WordPress (`musiclinkd.com`):
- `style.css`, `theme.json`, `functions.php`, `index.php`
- `assets/` — canonical design tokens (`tokens.css`), base styles (`main.css`), website design system (`musiclinkd.css`), responsive enhancements (`enhance.css`), and interactive animations (`main.js` with GSAP & ScrollTrigger)
- `parts/` — native navigation header (`header.html`) and footer (`footer.html`)
- `patterns/` — full 17-section marketing landing pattern (`patterns/landing.php`) and starter hero (`patterns/hero.php`)
- `templates/` — `front-page.html`, `page.html`, `single.html`, `404.html`, and `index.html`
- **CMS & Help Centre**: 11 production pages mapped from app engine (`/help/`, deep guides, `/about/`, `/pricing/`, `/cookies/`, and synced `/privacy/` & `/terms/` with ownership guarantees), all fully converted to native WordPress Gutenberg blocks for visual editing in WP Admin.
- **Media & Identity**: 55 brand and gallery assets imported into WordPress Media Library; `site_icon` and `custom_logo` configured. Full Gutenberg editor style parity enqueued in `functions.php`.
- **Email Design System**: FluentCRM block email template (ID 106) and cross-client FluentSMTP HTML signature (`templates/email/signature.html`).
- **Engine Health & Visual Admin**: `inc/engine-dashboard.php` provides a native visual dashboard at `/wp-admin/admin.php?page=musiclinkd-engine`, a Dashboard Widget on `/wp-admin/index.php`, and a REST telemetry endpoint (`/wp-json/musiclinkd/v1/sync-health`).

## Hardcoded content rule

User-visible UI copy belongs in Android resources rather than Compose literals. Demo/seed entities belong in seed providers. Real runtime values belong to application state, repositories, or the database.

The recovered hardcoded-content audit is maintained at [`guide/docs/hardcoded-content-audit.md`](guide/docs/hardcoded-content-audit.md). Treat it as an audit and migration backlog, not as proof that every listed hotspot still exists unchanged in the current source tree.
