## 2. `src/styles/liquefy-ui.css` — what it is

A vendored Tailwind-v4 interop stylesheet for the npm package `@liquefy-ui/core` (`^0.1.3`,
`package.json:19`), plus a `@liquefy-ui` shadcn registry entry at `components.json:28`. It is a
**complete second design system** — its own tokens, its own component styles, its own animation
vocabulary — living beside `src/styles.css` and sharing nothing with it.

## 5. Token drift inside these systems

`TOKEN-MAP.md §18` totals **2,569 off-token occurrences**, and that figure is the **`product` bucket
only** — `src/components/ui`, `kibo-ui` and `waves-cn` are the separate `vendor` bucket, and
`liquefy-ui.css` is in the `css` bucket. So:

### How much of the 2,569 sits inside these systems

**16 occurrences — 0.6%.** All of it is `src/lib/glass-variants.ts`, which counts as `product`
because it lives in `src/lib`, but is reachable only from `lab/glass.stories.tsx` through
`ui/glasscn/glass-button.tsx`. `per_file_drift` records it as `{"named_colour": 16}`;
`TOKEN-MAP.md §19` describes it as "the bridge to the unreachable `--lq-*` system … the file's fate
is a decision, not a swap", and counts a further 30 `rgba()` and 6 shadows in it that fall outside
the 2,569 groups.

**`src/styles/liquefy-ui.css` contributes 0 of the 2,569.** The count is extracted from string
literals in `src/**/*.{ts,tsx}`; a `.css` file has none. Its drift is of a different kind: 55
parallel custom properties that no app token maps onto.

## 6. Keep / import list

### Keep in place, do not touch

| Item | Rule |
| --- | --- |
| `ui/sonner.tsx` | App-reachable and load-bearing — `<Toaster/>` in `routes/__root.tsx:12` is the only renderer for 25 product files that call `toast()`. |
| `ui/avatar.tsx`, `ui/switch.tsx` | App-reachable via `ml/viewer.tsx` and `ml/work-form.tsx`. |
| `.storybook/preview.tsx`, `.storybook/layers.css` | The only importers of `liquefy-ui.css`. Either survives with it or is edited alongside it. |

### Candidates to import into the app — specific files, specific rules

Nothing in either system can be adopted as-is: every `ui/` file styles itself from shadcn's
`--primary` / `--accent` / `--muted` vocabulary, and every `lq-*` rule from `--lq-*`. Neither reads
the ink palette. What is worth taking is the **shape**, not the file:

1. **`src/styles/liquefy-ui.css:3552–3575` — the `@theme inline` pattern.** The comment there records
   a real constraint: `inline` is required so `var(--lq-*)` resolves at use time and survives a theme
   flip, rather than baking a build-time value. If `styles.css` ever gains a token that changes with
   theme, this is where the rule is written down. **Where it would go:** `src/styles.css`, beside the
   existing `@theme inline` block. Import the technique, not the 18 `liquid-*` utilities — none of
   them has a caller.
2. **`.storybook/layers.css:3` — the cascade-layer ordering rule.** One line, with a comment
   explaining that a vendored component sheet must sit after Tailwind's base reset (which zeroes its
   padding and radius) and before utilities. **Where it would go:** it is already in the right place;
   it only needs to be preserved if `liquefy-ui.css` is kept, and deleted with it otherwise.
3. **`ui/dialog.tsx` (104) and `ui/sheet.tsx` (122) — focus-trap and scroll-lock behaviour.** The
   app's `ml/kit.tsx:260` `Dialog` writes `role="dialog"` and `aria-modal` by hand and
   `ml/ui.tsx:481` `Sheet` likewise; neither gets Radix's focus trap, focus restore, `Escape`
   handling or body scroll lock. **Where it would go:** the behaviour into `ml/kit.tsx` / `ml/ui.tsx`,
   or those two `ui/` files adopted and re-tokenised to the ink palette. This is the only functional
   gap the audit found; everything else the app hand-builds, it hand-builds completely.
4. **`ui/tabs.tsx` (53) — roving-tabindex keyboard handling.** `ml/kit.tsx:113` renders
   `role="tablist"` without arrow-key navigation. Same disposition as above.
5. **`ui/label.tsx` (21) / `ui/input.tsx` (22) / `ui/textarea.tsx` (21) — 64 lines total.** The app
   writes `<label>` 44 times across 29 files and `<input>` 42 times across 26. These three are thin
   enough to re-token in one pass. Adopting them is a consistency decision, not a correctness one.

### 27 `@radix-ui` dependencies

All 27 are used only by `src/components/ui` (and one by `kibo-ui/reel`). So are `recharts`,
`embla-carousel-react`, `vaul`, `cmdk`, `react-day-picker`, `input-otp`, `react-resizable-panels`,
`react-hook-form` and `@liquefy-ui/core` — each has exactly one importer, and every one of those
importers is in the vendor bucket. `wavesurfer.js` has two: `waves-cn/wave-player.tsx` and
`src/lib/wave-cn.tsx`.

## 7. Delete list, and the risk of each group

### Group A — orphaned, reachable from nothing (39 files, 4,162 lines)

The 38 `src/components/ui/*.tsx` listed in §3 plus `kibo-ui/reel/reel-controlled.tsx`.

**Risk: lowest.** No import edge points at any of them from the app or from Storybook.
**What could break:** nothing at build time. `tsc` and the Vite build cannot reference a file no
edge reaches. **How it would show:** an editor auto-import that used to offer `@/components/ui/X`
stops offering it. Re-adding a file from the shadcn registry is one CLI call; `components.json` is
already configured.
**Caveat:** `ui/sidebar.tsx` (744) is the single biggest win and is already non-functional — its
`--sidebar-*` tokens are undefined repo-wide.

### Group B — Storybook-only (14 files, 2,281 lines)

**Risk: contained but real.** These are alive; they are simply alive somewhere that is not the app.
**What could break:** the Storybook build. `lab/glass.stories.tsx`, `lab/media.stories.tsx` and
`lab/stories-reel.stories.tsx` import them directly or transitively.
**How it would show:** `storybook build` fails with an unresolved import, or the story page renders
an error boundary. The app build is untouched — no route reaches any of them.
**Rule:** each of these deletes together with its story, or not at all. Deleting
`ui/carousel.tsx` without `kibo-ui/stories/index.tsx` breaks the reel story; deleting `ui/card.tsx`
or `ui/slider.tsx` without `lab/media.stories.tsx` breaks the media story.

### Group C — the liquefy cluster (5,191 lines)

`src/styles/liquefy-ui.css` (3,575), `src/lib/styles-prop.ts` (568), `src/lib/provider.tsx` (141),
`src/hooks/use-liquid-glass.ts` (89), `src/lib/glass-variants.ts` (57), `ui/liquid-chip` (110),
`ui/liquid-segmented` (119), `ui/liquid-toast` (119), `ui/liquid-alert` (79),
`ui/glasscn/liquid-glass` (296), `ui/glasscn/glass-button` (38), plus `.storybook/layers.css`, the
two `liquefy-ui.css` import lines in `.storybook/preview.tsx`, `lab/glass.stories.tsx`, the
`@liquefy-ui/core` dependency and the `@liquefy-ui` registry entry in `components.json`.

**Risk: contained, but the cluster is all-or-nothing.** It is a closed loop with one entry point.
**What could break:** `lab/glass.stories.tsx` — the side-by-side comparison of the app's own chips,
segmented control and buttons against `@liquefy-ui` and `@glasscn`. That comparison is the only
artefact the cluster produces.
**How it would show:** Storybook build failure on the unresolved import, or the "Lab/Glass" story
page vanishing from the sidebar. Nothing in the app changes — no product file uses an `lq-*` class or
a `liquid-*` utility.
**Two loose ends if the cluster goes:** `src/lib/glass-variants.ts` takes 16 of the 2,569 with it, so
the headline drops to 2,553; and `src/lib/wave-cn.tsx` (the second `wavesurfer.js` importer) is not
part of this cluster and would need its own check.

### Group D — dependencies

Removing a `ui/` file does not remove its package. `@radix-ui` ×27, `recharts`, `cmdk`, `vaul`,
`embla-carousel-react`, `react-day-picker`, `input-otp`, `react-resizable-panels`, `react-hook-form`,
`@liquefy-ui/core` become unreferenced once Groups A–C go.

**Risk: build-time only, and it is the risk of acting too fast rather than too slow.**
**What could break:** a `bun remove` for a package something still imports.
**How it would show:** `tsc` fails on a missing module, or the Vite build fails to resolve. Every one
of these has exactly one importer today, so the check is a single grep per package before removal.
`tw-animate-css` is the exception — `styles.css:3` imports it, and 3 product occurrences of
`animate-in` / `animate-out` remain against 37 in vendor, so it stays regardless.
