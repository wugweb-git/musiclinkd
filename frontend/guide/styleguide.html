Typography Scale & Editorial Specimen Showcase Stable Android Compose & Material 3

Editorial typography scale designed for 360dp mobile viewports. Display and Headline tokens use Inter Tight with negative letter-spacing for high-impact editorial headers. Body and Label tokens use Inter for maximum legibility.

TokenFluid value (360px → 1440px)Usage
type-110px → 12pxMicro labels, captions, badges, metadata (was 7–13px, 21 near-duplicate sizes)
type-214px → 18pxBody text, default UI copy, small headings
type-320px → 28pxSection headings, card titles
type-428px → 44pxDisplay, hero headlines

4 tokens, exponential ~×1.4–1.6, each a CSS clamp() scaling continuously with viewport width across the 360–1440px breakpoint range — not a fixed px value per breakpoint. Every one of the 1,055 hardcoded font-size declarations across this file now resolves through these 4 tokens. The Android Compose sp scale below maps to its own platform-native steps per governance.md §4 and is intentionally separate.

Per-breakpoint behavior

Font, weight, line-height, letter-spacing and color don't change across breakpoints in this system — only the computed size does, continuously. This table evaluates each clamp() live at the four real breakpoints (defined here) instead of hardcoding numbers that could drift out of sync with the actual token, which is exactly how the old "Wide = 1440px" claim in the Breakpoints table went stale against the real CSS.

Native Component Catalog New

Jetpack Compose components from app/UnifiedComponents.kt, mapped onto this system's canonical tokens. A source doc pasted alongside this catalog specified Plus Jakarta Sans, Material Symbols icons, and #10B981 for success — all three conflict with this system's typography (Inter/Inter Tight), icon family (Lucide only, per README's Boundaries section), and success color (#22C55E).
